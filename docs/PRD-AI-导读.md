# AI 导读 —— 产品规格说明书（PRD）

> 版本 v0.1 · 2026-10-08 · 状态：原型已定稿，待实现
> 原型参考：`prototypes/ai-first-reader-v5.html`

---

## 1. 产品定位

**AI 导读**：一种「互动式阅读」，替代传统的「单向阅读」（人读原文）。

- **AI 负责读和总结**：AI 通读论文，产出一份结构化的「导读」——告诉用户这篇讲了什么、该怎么读、关键在哪里。
- **人负责判断和形成观点**：用户不是被动接受 AI 的总结，而是对 AI 提出的每条关键点做判断（认同 / 存疑 / 不认同），写下自己的看法，最终形成自己对这篇论文的观点，并用检测题自检理解。

一句话：**AI 把论文「读」了，人把 AI 的理解「审」了，最后人形成自己的观点。**

---

## 2. 核心价值与差异化

| | 传统 AI 助读 | AI 导读 |
|---|---|---|
| 主体 | 人读原文 | AI 读论文 |
| 第一屏 | 原文三栏 | AI 的导读（阅读建议在前） |
| 原文定位 | 主视图 | 右侧「点击才打开」的对照视图 |
| AI 角色 | 被动工具（划词解释、问答） | 主动读者（读完主动讲 + 给阅读地图） |
| 人的角色 | 读者 | 判断者 + 观点形成者 |
| 价值主张 | 读得更顺 | **不用全读，且不被 AI 带偏** |

差异化核心：**互动式阅读 + 判断审核 + 形成自己的观点**，而非「AI 单向灌输」。

---

## 3. 核心概念

- **导读（Reading Guide）**：AI 读完论文后生成的结构化产物，包含阅读建议、一句话总结、导读轨迹、整体判断、检测题。
- **导读轨迹（Reading Trail）**：AI 从头读到尾的「停顿」序列，每处停顿是 AI 读到一个关键点时的一句口语化、有态度的发言，带原文锚点。
- **判断（Judgment）**：用户对导读轨迹每处停顿的裁决——认同 / 存疑 / 不认同。
- **我的观点（My View）**：用户读完 + 判断后，形成的对整篇论文的看法（文本或语音）。
- **检测题（Quiz）**：AI 生成的 3–5 道选择题，检验用户对内容的理解。
- **锚点（Anchor）**：原文定位信息（页码 + 段落/句子），点击后右侧 PDF 打开并定位、高亮。

**整体布局：左导读 + 右原文（双栏），右栏点击后才打开。**

```
┌─────────────────────────────────────────────────────┐

├───────────────────────────────┬─────────────────────┤

│ ② 一句话总结                  │   （点击锚点链接后   │
│ ③ 导读轨迹（6 处停顿）        │    打开 + 定位 +     │
│    每处：AI 发言 + 判断       │    锚点高亮）        │
│          + 看法输入           │                     │
```

自上而下的阅读顺序：**阅读建议 → 总结 → 轨迹 → 整体判断 → 我的观点 → 检测题**。

**导航结构**：首页 = 阅读（AI 导读）。顶栏保留「书架」「市场」两个菜单入口（这两个页面暂不改造，后期再改）。

## 5. 模块详细规格

### 5.1 阅读建议（最前）

AI 生成的「阅读地图」，告诉用户不需要全读。**放在最前**（一打开先看到）。

- **精读**（careful）：值得读原文的 2–4 处，每处带原文链接（点击 → 右侧 PDF 锚定）。
- **略读**（skim）：扫一眼即可的章节，带原文链接。
- **重点盯**（focus）：读的时候要盯住的 3–5 个关键点（文字列表）。

### 5.2 一句话总结

AI 读完的一句话（1–2 句），给出论文核心主张。

### 5.3 导读轨迹（核心）

AI 从头读到尾的停顿序列，**6 处左右**（AI 按论文内容自适应，5–8 处）。

每处停顿包含：

| 字段 | 说明 |
|---|---|
| `where` | 位置（Abstract / §1 / §3 / Figure 2 / Table 2 / 读完疑问） |
| `type` | 类型：📍定位 / 💡发现 / 🤔存疑 / 📊图表 / 🧭结论 |
| `says` | AI 的发言——口语化、第一人称、有态度（「我存疑」「最巧的一笔」「要打个折」） |
| `anchor` | 原文锚点（页码 + 段落 + 高亮句），点击「看原文 ↗」右侧打开 |

**用户对每处停顿的操作**：
- **判断**：✓ 认同 / ? 存疑 / ✗ 不认同（三选一，可改）
- **看法**：点「💬 说点什么」展开输入框（文本）+ 🎤 语音输入

### 5.4 整体判断（最后）

AI 读完后的总体判断（2–3 句）+ 星级（★ 1–5）。**浅色卡片**，非黑色块。

### 5.5 我的观点

用户在读完 + 判断后，形成自己的观点。**大输入框 + 🎤 语音输入**。

引导语暗示「别照单全收」：上面 AI 的观点你认同几条？哪些不同意？为什么？

### 5.6 检测题目

AI 根据**论文长度 + 难度**生成的 3–5 道**选择题**（短/易 → 3 道，长/难 → 5 道），检验理解。选择后：对错高亮 + 显示解析。

### 5.7 右侧 PDF 原文

- **默认关闭**（页面为单栏）。
- 点击任何锚点链接（阅读建议里、轨迹里的「看原文 ↗」）→ 右侧打开 PDF 原文，**定位到对应页/段落，锚点句子高亮**。
- 点「✕」关闭，回到单栏。

### 5.8 重新生成

导读支持「重新生成」：用户对当前导读不满意，可一键重新生成（换一批停顿/观点/检测题）。异步执行，`status` 标记生成中，完成后刷新。

### 5.9 观点导出

用户**认同的观点**（judgments 中 `agree` 的轨迹）+ **自己输入的看法**（notes）+ **我的整体观点**（my_view），支持**整体导出**为一个 Markdown 文档，便于留存 / 粘贴到飞书文档。

---

## 6. 交互规格

| 交互 | 行为 |
|---|---|
| 点「看原文 ↗」/ 阅读建议链接 | 右侧 PDF 打开 → 定位 → 锚点高亮 |
| 判断（认同/存疑/不认同） | 三选一，选中高亮（绿/黄/红），可改选，实时记录 |
| 「💬 说点什么」 | 展开输入框 + 语音按钮 |
| 🎤 语音输入 | 录音 → 转文字 → 填入输入框 |
| 检测题选项 | 点击后：正确绿 / 错误红 + 高亮正确答案 + 显示解析 |
| 我的观点「记录」 | 提交存储 |
| 「重新生成」按钮 | 触发异步重新生成导读 |
| 「导出观点」按钮 | 导出认同观点 + 看法 + 整体观点为 Markdown |

## 7. 数据模型

### 7.1 AI 导读产物（后端生成，存 `paper.reading_guide` JSONB）

```json
{
  "version": 1,
  "status": "generated",
  "reading_plan": {
    "careful": [
      {"ref": "§3", "label": "Method", "note": "自省检索的闭环", "anchor": {"page": 4, "section_index": 2, "highlight": "retrieves from this memory…"}}
    ],
    "skim": [
      {"ref": "§2", "label": "Related Work", "anchor": {"page": 3, "section_index": 1}}
    ],
    "focus": ["① 自省检索消融", "② Table 2 领先<1%", "③ 可解释性"]
  },
  "summary": "一句话总结文本",
  "trail": [
    {
      "id": "t1",
      "where": "ABSTRACT",
      "type": "location",
      "says": "打开这篇，一句话说清……",
      "anchor": {"page": 1, "section_index": 0, "highlight": "an agentic framework…"}
    }
  ],
  "verdict": {"text": "方向对，方法有巧思……", "stars": 4},
  "quiz": [
    {"id": "q1", "q": "核心创新是什么？", "options": ["A…", "B…", "C…", "D…"], "answer": "B", "explain": "答案 B……"}
  ]
}
```

### 7.2 用户交互产物（前端提交，存 `paper.user_engagement` JSONB）

```json
{
  "judgments": {"t1": "agree", "t2": "doubt", "t3": "reject"},
  "notes": {"t1": "我的看法文本"},
  "my_view": "我的整体观点",
  "quiz_answers": {"q1": "B", "q2": "C"},
  "updated_at": "2026-10-08T…"
}
```

### 7.3 锚点机制

- 数据来源：`parsing.py` 的 sections 已有 `page_range`，需**增强为段落级 page 记录**（每个段落/chunk 记 `page` + `text`）。
- 锚点 `{page, section_index, highlight}` 映射到原文位置。
- 前端 PDF.js 打开 PDF → 跳转到 `page` → 用 `highlight` 文本定位 → 高亮该句子。

## 8. 后端实现要点

1. **新增 FIPAI task `generate_reading_guide`**：输入 `parsed_doc`，输出结构化导读（reading_plan / summary / trail / verdict / quiz，其中 quiz 数量由 LLM 按论文长度+难度生成 3–5 道），其中 trail 的每条 `anchor` 必须引用真实存在的 section/段落（防止幻觉，参照现有 `answer_with_citations` 的引用校验思路）。
2. **增强 parsing**：段落级 page 记录，供锚点定位。
3. **新增 `ReadingGuide` 存储**：`paper.reading_guide`（JSONB）+ `paper.user_engagement`（JSONB）。
4. **新增 API**：
   - `POST /api/papers/{id}/reading-guide` —— 触发导读生成（异步，上传后自动触发）；带 `force=true` 支持重新生成
   - `GET /api/papers/{id}/reading-guide` —— 取导读产物
   - `PUT /api/papers/{id}/engagement` —— 存判断/看法/观点/检测答案
   - `GET /api/papers/{id}/engagement/export` —— 导出认同观点 + 看法 + 整体观点（Markdown）
   - `GET /api/papers/{id}/pdf` —— PDF 原文（供前端 PDF.js 渲染）
5. **导读生成时机**：上传论文 → 解析完成后 → 自动触发 `generate_reading_guide`（异步任务，状态 `status` 标记）。

---

## 9. 前端实现要点

1. **布局重构**：三栏 → 左导读 + 右 PDF（双栏，右栏点击才出现）。
2. **组件拆分**：`ReadingPlan`、`Summary`、`ReadingTrail`（含 `TrailStop`）、`Verdict`、`MyView`、`Quiz`、`PdfPanel`。
3. **PDF 渲染**：引入 PDF.js，右侧面板渲染 PDF 页，实现「跳转 page + 文本高亮」。
4. **判断/看法/观点**：本地状态 + 提交 `PUT /engagement`。
5. **语音输入**：MVP 用浏览器 Web Speech API（SpeechRecognition），后续可接飞书/ASR。
6. **检测题**：选项交互 + 对错高亮 + 解析。

## 10. 实现阶段与里程碑

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| **P1 后端导读生成** | FIPAI task + 存储 + API + 段落级 page | `generate_reading_guide` 能产出含正确锚点的完整导读，API 可取可存 |
| **P2 前端重构** | 双栏布局 + 各模块 UI + PDF.js 锚定高亮 | 左导读各模块渲染，右侧 PDF 点击打开 + 定位 + 高亮 |
| **P3 交互落地** | 判断/看法/观点/检测题全链路 + 提交存储 | 用户交互数据可提交、可回读、可持久化 |
| **P4 打磨上线** | 语音输入 + 移动端适配 + 性能 + 部署 | 语音可用，`reader.fipai.cn` 上线，旧三栏下线 |

---

## 11. 边界（不做什么）

- ❌ 不做多论文对比 / 综述生成
- ❌ 不做团队协作、分享、评论
- ❌ 不做复杂工作流 / 自动化 agent
- ❌ 不做移动 App（MVP 为响应式 Web）
- ❌ 不引入新 LLM 供应商（复用现有 FIPAI）
- ❌ 导读轨迹不做「实时打字机」效果（MVP 一次性呈现）

---

## 12. 风险与待定项

- **AI 幻觉**：trail 的锚点必须引用真实段落，需引用校验（参照现有 citation 校验）。
- **PDF 锚定精度**：段落级定位的准确度，需在 P1 验证；不达标则退化为「页级定位 + 整页高亮」。
- **语音输入**：浏览器 Web Speech API 的中文识别质量，若差则接入飞书/第三方 ASR。
- **导读生成耗时**：LLM 生成 6 处轨迹 + 检测题的耗时，需异步 + 缓存，避免阻塞。
（原待定项已定：支持重新生成；检测题按长度/难度生成 3–5 道。）
